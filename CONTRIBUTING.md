# Contributing

Contributions are welcome through issues and pull requests. Start with a bounded research question or model failure, identify the exact baseline and source, and describe which Product or Network decision the change could affect.

For a model change, include its assumptions, an alternative or failure case, and the smallest test or fixture that distinguishes the proposal from the current model. Keep candidate records marked `candidate-unadmitted` with `authority_effect: none` unless an actual owner decision and its evidence are part of a separate governed process. A simulation result is not a real sale or research finding.

Run the commands in [README.md](README.md) before opening a pull request. Keep generated fixtures in sync with their scripts. Source files in `examples/engineer-assessment/source/` form a pinned public snapshot; changes to them require regenerating Product 001's `source-manifest.json`, crosswalk and task catalog, and explaining the change in the pull request.

Do not submit real participant answers, recordings, contact details, credentials, private employer data, or unpublished case-bank material. Use authored synthetic fixtures for public examples. Changes that would enable employer access, personal-data sharing, funding, token issuance or payouts need their own Product and governance decisions; a merged model proposal does not enable those effects.
